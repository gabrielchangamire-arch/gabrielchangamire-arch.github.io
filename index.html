01 // About

I am a Computer Science student at Bellevue College with a 3.67 GPA, an Associate's degree with Honors, and a drive to build things that matter. I came to CS not just to code, but because I believe technology is one of the most powerful levers for reducing suffering in the world.

Most recently I built FleetPulse, a local-first Linux fleet reliability and incident-response platform: a psutil-based telemetry agent with a crash-safe spool and idempotent replay, FastAPI ingestion into PostgreSQL, Redis Stream workers, an Nginx/TLS edge, Prometheus/Grafana SLO dashboards, controlled failure-and-recovery drills, and CI supply-chain gates — with every reliability claim backed by evidence runs committed to the repo. It builds on the production-shaped AWS backends I shipped earlier this year: a FastAPI task manager on EC2/RDS/S3 and a distributed job queue on SQS and DynamoDB.

This summer I am a Production Engineering Fellow in the Meta × MLH program, mentored weekly by senior Meta Production Engineers. I administer a CentOS Stream 9 server on DigitalOcean that runs a MySQL-backed Flask app in production: I wrote its systemd unit, built the Bash redeploy pipeline with curl health checks, and recently audited the box myself — found the database port exposed to the internet, and closed it the same day while keeping the site online. Along the way I started contributing upstream to the tools I use: a parsing fix merged into psutil (the library behind Ansible, Datadog, and most Python system monitoring) the same day I submitted it, and a complexity refactor merged into Glances.

I work comfortably with modern development tools and frameworks, and I use them to augment and accelerate my own work. I particularly enjoy the orchestration side of engineering: chaining tools together into workflows that handle technical tasks quickly and reliably.

I am part of the Mentors in Tech program at Bellevue College. My mentors include Spencer Nelson, a Principal UX Engineer and Manager at Microsoft, and Starlight Romero, a Principal Platform Engineer. Longer term, I want to work in production and reliability engineering — keeping large-scale systems healthy — with AI as one of the sharpest tools I build with.

FleetPulse
A local-first Linux fleet reliability and incident-response platform, built to demonstrate production engineering practice with measured evidence, not scale claims. A container agent collects bounded telemetry with psutil — the same library I've contributed to upstream — and survives restarts via a bounded SQLite spool with capped-backoff, full-jitter retries. FastAPI ingestion commits telemetry, idempotency state, and outbox events atomically to PostgreSQL; Redis Stream workers process downstream; an Nginx/TLS edge load-balances with cache-aside fleet reads. Prometheus, Grafana, and Alertmanager track SLOs; the whole stack deploys reproducibly to Docker Compose or local Kubernetes (kind/k3d), and has been through controlled failure/recovery drills and performance runs — raw evidence for every claim is committed under evidence/.

Distributed Job Queue System
Producer/consumer backend: a FastAPI API submits jobs to SQS, a separate worker process pulls them off the queue, runs the handler, and persists state to DynamoDB. Implements idempotency keys, bounded retries with dead-letter handling, and CloudWatch-shaped logging. The queue and store are interfaces with two implementations (in-memory and AWS), so the full system runs end-to-end locally without credentials and the same code targets real AWS via env vars. 19 tests including moto-mocked SQS and DynamoDB integration.

03 // Open Source
Merged Upstream · Linux
psutil — swap_memory() fix
psutil is the cross-platform process and system monitoring library behind Ansible, Datadog, and countless production stacks — 300M+ downloads a month. On arm64 Linux, swap_memory() crashed when the kernel printed a /proc/meminfo field with no space after the colon — a fixed-width %8lu printf quirk in the kernel's own procfs code that appears once shadow call stacks pass 10 GB. I root-caused it to the kernel source, reproduced it in an arm64 container with a mocked procfs, found that the existing upstream PR only fixed the sibling function, and shipped the complementary fix with a regression test. Merged by the maintainer the same day.
